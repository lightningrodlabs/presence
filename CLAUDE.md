## True today (facts, not goals)

- **Post-Phase 3 carrier facts** (landed 2026-07-29, merge `492197b`; adversarially reviewed; field validation landed same day as Phase 3.5 — the release gate is satisfied). The FSM is the **only** WebRTC carrier — SimplePeer is deleted, not just unreachable: no `simple-peer` dependency, no `SimplePeerTransport`, no impl preference (`resolveWebrtcImpl`/`webrtcImplFor`/`peerImpl` decisions are gone; `webrtcAvailableFor(peer)` — does the peer hold the `sdp-fsm` cap — is the one WebRTC gate, applied at both video handshake ends). Screen share runs on two FSM transports (out=sharer, in=viewer) over the capability-gated `SdpFsmScreen` signal type; incoming screen signals are routed by the sender's declared role (`decideScreenSignalRoute` in `transport/screen-signal-policy.ts`), never by connectionId, because each side's FSM allocates its own. The screen InitRequest/InitAccept handshake and all pending-accept maps are deleted — the FSM acceptor creates state lazily from the first offer; only `_pendingInits` (video initiator pacing) survives. `SdpData` is retired in the wire contract (`emits:false/parses:false`, explicit drop arm). Declared interop change: screen share does not interoperate with v0.14.8 in either direction; video with v0.14.8 still works; no WebRTC at all with peers lacking the `sdp-fsm` cap. Auto-flip (`decideAutoFlip`, `decideCarrierSwitch`, `auto-flip-policy.ts`) is deleted per the unscheduled-table decision. `_screenShareStreams` is wired (set on remote-stream, cleared on close/error/leave/disconnect). The stale-connection supervisor is kept but always stands down in production — every live transport owns recovery.
- Signals is a **module-layer fallback**, not a `PeerTransport` — `ui/src/transport/types.ts` says so explicitly. Since Phase 4, `PeerTransport` **is** the type annotation for the store's three transport fields, so it is a real constraint, not a decoration.
- **Post-Phase 4 facts** (landed 2026-07-29, branch `feat/phase-4-say-what-signals-is`; adversarial review pending before merge). The `getRTCPeerConnection` escape hatch is **deleted** — the pc never leaves the transport. ICE forensics are transport-emitted `ice-diagnostic` events (listeners attached at `onPeerCreated`, one set per peer session, aborted on close/replace); the store keeps `_iceTimings` and the `IceDisconnectedAt` bookkeeping from those events, and the poll-until-pc-appears attach machinery is gone. Per-peer control is typed: `prioritizeAudio(peer, {videoMaxBitrateBps})`, `refreshMediaForPeer(peer, stream)`, read-only `getIceConnectionState(peer)` (stale-net input only); `recreateDataChannel`/`restartIce` deleted (zero callers). `statsFor(peer)` (`transport/carrier-stats-policy.ts` over `carrierFor`) is the one carrier+stats answer — the stats panel no longer hand-branches, and its carrier keys on `connected`, not slot existence. `decideAudioLink`/`buildPeerLinkSnapshot` (`ui/src/peer-link-policy.ts`) own the audio-link roll-up: **observed media flow beats the signals-reachability veto** (a pong outage no longer marks a peer with live WebRTC audio 'absent'); UI copy reserves "connected" for ICE+DTLS (`observersHearing`/'heard by', 'not reachable by you'). The `'start-ice-monitor'` route handler is renamed `'signaling'`. No wire-surface change; `PeerLinkSnapshot` semantics pinned by tests.
- **Post-Phase 2 presence facts** (landed 2026-07-28, branch `feat/phase-2-presence-clock`). The **present** predicate has one authority: `computePresentPeers` (`ui/src/presence-policy.ts`), exposed as `StreamsStore._presentPeers` — ping-fresh OR media-flowing, re-evaluated on a presence tick every `PING_INTERVAL`. Chimes, tiles, all three grid counters, `globalPresenceSet`, and phantom exclusion key off it; join/leave sounds are store events (`peer-joined-presence`/`peer-left-presence`) decided by `decidePresenceSoundEvents` with a 2-tick leave dwell, so a presence flap shorter than the dwell makes no sound. `StreamsStore.clock` (`ui/src/clock.ts`) is the single time authority — every timing site in the store and the controllers' `peerLastRecvMs` stamps route through it; wall-clock remains only where cross-peer wire timestamps are compared (jitter/transit EWMAs) and in view-paint timers. The presence-family constants live in `presence-policy.ts` with one window per predicate (`PRESENT_STALENESS_MS`, `MEDIA_LIVE_WINDOW_MS`, `OBSERVER_FRESHNESS_MS`, `LAST_SEEN_FRESH/GONE_MS`, `PRESENCE_LEAVE_DWELL_MS`). **Not consolidated by Phase 2**: transport-layer graces (ICE-disconnected 15s, SDP timeout 15s, init retry 5s, ICE-monitor attach budget), the handshake TTL (`PENDING_HANDSHAKE_TTL_MS` 20s), voice/filmstrip internal stats windows and local send stamps, and the filmstrip display-hold TTL (documented as paint, not liveness). The lobby (`room-online-agents.ts`) still runs a separate presence model on bare 10000ms literals — out of Phase 2's scope and the next place this pattern will regrow. Declared behavior changes: signals-audio liveness window 2000→3000ms in `audioLinkFor`; a signals-only peer with stale pongs now gets a tile; leave chimes are dwell-delayed ~4s.
- `nix develop -c npm run verify` is the gate: 552 unit tests (222 package + 330 ui — Phase 3 deleted ~80 SimplePeer/auto-flip tests; Phase 4 added ~38 across carrier-mode, carrier-stats, peer-link, and the transport's ice-diagnostic/per-peer-control surface, including the review-F1 replacement-abort and destroy pins) plus a `tsc --noEmit` of both workspaces, in a few seconds. CI runs the same command on push and PR to `main-0.6`. (Phase 0 landed this; the `ui/` typecheck is green at `strict: true`, but only against a built `packages/webrtc-peer` — `verify` builds it first.)
- `StreamsStore` is now **constructible** under `vitest` in the node environment (Phase 2 item 2): the constructor only assigns fields and defines derived stores; everything ambient lives in `start()`. `start()` still requires a browser, so wiring beyond construction (transports, signal handlers, reconcilers) remains unvalidated in unit tests until Phase 6's dependency injection. `ui/src/__tests__/streams-store-construction.test.ts` is the guard; extract pure decision functions rather than characterization-testing the class.
- **Post-Phase 1 carrier facts.** Signals carries a present peer unless WebRTC is `connected` (ICE + DTLS up) — the complement of *media flowing*, not of *an attempt existing*; the rule is in `ui/src/transport/carrier-coverage.ts`. "Present" there means the **present predicate** (`_presentPeers`), not ping-freshness: keying the send set on `_activeAgents` alone was §3.1(b) one-way audio, fixed in the PR #4 review pass. Every `ConnectionPhase` is routed by `routeTransportPhase` (`transport/media-event-policy.ts`), exhaustive over the union, with `failed`/`idle`/`closed` clearing the slot and `signaling` adopting a new `connectionId` when the transport replaced an FSM underneath us — **`ConnectionManager.fsm.destroy()` emits no transition, so a connection can disappear with no event at all**; never assume you will be told. The FSM owns transport recovery and the pong-driven teardown stands down (`transport/stale-connection-policy.ts`) — since Phase 3 that is every link. A link gets WebRTC at all only if the peer's payload declares (or, for pre-caps builds, is inferred to hold) the `sdp-fsm` capability — `conversationPayloadCaps` is the one capability read (`StreamsStore.webrtcAvailableFor`). **Field validation is partial** (Phase 1.5): the transport stack and carrier policy are exercised nightly against real RTCPeerConnections — establishment, silent-drop flap, handover in both directions — by `ui/harness/carrier-handover.spec.ts`; since Phase 3.5 the screen-share FSM path is too (`ui/harness/screen-share.spec.ts` — lazy establishment over `SdpFsmScreen`, dir-routing under mutual share, malformed-dir drop, teardown on silent drop). The slot rules are shared code — `decideSlotWrite` (`transport/media-event-policy.ts`) is executed by both the store and the harness — but the dispatch glue is mirrored and no conductors run, so the store's own wiring remains unvalidated until Phase 6. Known bounded exception to the carrier invariant (recorded 2026-07-28): during `reconnecting`/`disconnected` the slot keeps `connected: true` (`routeTransportPhase` → `transport-owns-recovery`), so a peer can be off signals with no media flowing for the length of the transport's recovery window — and clearing a wedged FSM slot depends entirely on the FSM emitting `failed`.
- **Cross-version interop with ≤ v0.14.7 is a declared non-goal** (business decision, 2026-07-28); Phase 3 extended the consequence to v0.14.8 screen share (declared in its section of the assessment). The capability gate (`webrtcAvailableFor`; formerly `resolveWebrtcImpl` rule 0) is what enforces it. *Forward* interop is guarded by Phase 1.5's wire-contract gate — wire surface declared once and snapshot-tested, a per-release compat-corpus fixture, capability declared in the payload (`caps`) rather than inferred by field-probing — not by building old versions.

## The unit of change

Decisions go in pure functions: snapshot in, tagged union out, carrying a `reason`. Table-driven tests, no mocks. `ui/src/transport/media-event-policy.ts` is the template — copy its shape. (The former template, `auto-flip-policy.ts`, was deleted with SimplePeer in Phase 3.)

- **Exhaustive `switch` over a union type**, so an unhandled case is a compile error rather than a silent drop. `_dispatchMediaEvent` dropping five of eight `ConnectionPhase` members is the bug this prevents.
- **One authority per concept, one exported name.** A second implementation must delete the first. Adding a parallel path is the cheap wrong move and is how this codebase acquired 21 liveness sources.
- **Every important mock needs a negative control** — a test that fails if the mock cannot reproduce the bug the mock exists to catch. `MockRTCPeerConnection` cannot throw, which is why the `InvalidStateError` fix in `rtc-peer.ts` has no coverage and would survive being inverted.
- **Chase decision coverage, not line coverage.** The library sits at 90% and the orchestrator at 0%; every production bug has been in the orchestrator.
- **An abstraction not used as a type annotation gets deleted, not kept — or made real.** `PeerTransport` looked like a constraint and imposed nothing for three phases; Phase 4 made it the annotation on the store's transport fields, which is what turned "don't reach into the pc" from a review rule into a compile error.

## Working agreements

1. **Replace or declare.** Every change either names the mechanism it replaces, or states explicitly that it adds a parallel one and why. "Runs in parallel with X; X remains the source of truth" is how this codebase acquired four parallel models — it requires a justification, not a passing mention.
2. **No new threshold without a named predicate.** Six liveness clocks arrived one constant at a time. A new timeout must say which predicate it serves and reuse that predicate's clock.
3. **Prose cites code or gets deleted.** An invariant comment names the `file:line` it constrains. Every document gets `Status: ACTIVE` / `SUPERSEDED (see X)` / `HISTORICAL`, following `docs/WEBRTC_PEER_CLAIM2_DATACHANNEL_GATING.md`, which does it correctly. A design doc marks each item landed or not-landed once it ships. Living prose cites files and tests, not commit hashes — the Phase 1 branch rewrite invalidated four hash citations.
4. **Decisions become pure functions before they become complicated.** `ui/src/transport/media-event-policy.ts` is the template: plain-object in, tagged union out, table-driven tests, no mocks.
5. **The gate runs, or it isn't a gate.** A disabled workflow, an unrun typecheck, and an unenforced `strict` flag are all recorded intentions, not constraints.
6. **One intent per branch.**
7. **A conclusion may not dismiss field evidence on the strength of passing tests.** This happened (`12cb027`, then `c143cda` six weeks later proved it wrong). The mocks in `packages/webrtc-peer` cannot throw, so they cannot reproduce the failure modes that actually occur in the field.
8. **A fix names the symptom's previous fixes.** Use "supersedes `<hash>`" in the commit message. The same pane-survival symptom was fixed three times in three layers over 71 days, and the third broke an invariant the first documented.
9. **Every phase PR gets an adversarial review by a session that did not write it**, reading only the diff and the code. The second cause of the §3.1(c) wedge was found exactly this way, before the field found it. The authoring session's self-review converges to agreement with itself; independence is the property that caught it.
