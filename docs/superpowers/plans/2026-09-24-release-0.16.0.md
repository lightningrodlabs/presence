**Tech Stack:** Holochain 0.7 (hdk 0.7.0, hdi 0.8.0), `@theweave/api` 0.7.0-dev.x, Moss 0.16.0-dev.x, Lit + Svelte stores, vitest, tryorama, Playwright nightly suite.

### What kind of release this is

The shipped 0.15.x line (0.15.0 to 0.15.6) is already the Holochain 0.7 line. Every 0.15.x entry in `fixtures/releases.json` records the same `happSha256` (`e707d896…`). This release changes the happ for two reasons:

1. The tile order changes the coordinator zome. `get_all_agents` returns `Vec<AgentJoin>` instead of `Vec<AgentPubKey>` (`dnas/presence/zomes/coordinator/room/src/all_agents.rs`).
2. The coordinator change `6f7b87e` (local gets in the post-commit signal chain, 2026-08-13) never shipped. It ships now.

The integrity zome source did not change since `097f390`. The DNA hash covers the integrity zomes, not the coordinators. If the toolchain or the lockfile moved, a rebuild can still change the integrity wasm bytes. Therefore "DNA bump" is a claim to measure, not to assume. Task 6 measures it with `hc dna hash`. The two outcomes are:

- The hash is equal. The DNA is unchanged, but the happ changed, and Moss updates a Tool in place only when the happ bytes are equal. So a group adds 0.16.0 as a new Tool install. Moss gives every new install a new random network seed (Moss `group-store.ts`, `installAndAdvertiseApplet`), so the 0.16.0 install is a separate network from the 0.15.x install.
- The hash differs. The DNA changed too. The 0.16.0 install is a separate network for that reason as well.

In both cases 0.15.x and 0.16.0 agents do not see each other, and no user takes a manual step: one group member adds 0.16.0, and the others join that install. Compatibility with 0.15.x is not a goal (see Decisions). The notes must state the measured DNA outcome, because it is a fact about the release.

## Global Constraints

- The release branches off `main-0.7`, and it ships from `main-0.7`. `main-0.6` is not part of this release.
- Run all tests and all commands that need dependencies with `nix develop -c`.
- `nix develop -c npm run verify` is green at every merge into `main-0.7`.
- The `dna-tests` CI job is green after the tile-order merge (it runs `tests/src/room/room.test.ts`).
- `ui/package.json` pins `@theweave/api` to a registry version. A `file:` link must not reach `main-0.7`.
- The build sets `HAPP_CHANGE=1` and uses `npm run package`, not `npm run package:ui`.
- Record hashes as raw sha256 of the webhapp and of the members that `hc web-app unpack` extracts (`docs/RELEASING.md` step 6). Do not paste `npm run hash` output without that check.
- `gh release create` takes `--repo lightningrodlabs/presence`.
- Do not merge the curation PR before the Moss release that carries both services is published.
- No Claude co-author lines in commits or PR bodies.
- Use one intent per branch. Every merge gets a review by a session that did not write the branch (working agreement 9).
